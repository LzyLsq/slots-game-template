# WebP + 本地 StoreKit 2 Xcode

共 20 款 F13–F31、F33（仓库没有 F32）。每款维持 DBGame 和 Fxx_H5 两个工作文件夹；README 等是说明文件。原始源资源及旧工程未覆盖，只有本轮发布资源转换为 WebP。

## 打开与本地购买测试

1. 进入要测试的游戏文件夹，双击 DBGame 里的 .xcodeproj。不要双击网页 index.html。
2. 选择该游戏的 LocalTest Scheme，选择 iPhone 模拟器，再 Run。标准款先注册本地账户；F25–F28 按各自账户方式进入。
3. 打开商店购买。本地 .storekit 模拟付款，不扣真钱。等待“已验证并到账”结果；取消/待批准/失败不发币。
4. Product → Test 运行项目内 4 项回归；已实际执行 20 款共 80 项。

最低部署 iOS 15.4；本轮实际运行测试为 iOS 17.5 模拟器，不是最低系统真机验证。原生界面/网页壳为 Objective-C，StoreKit 2 后端保留 Swift，与前面的混合方案相同。

## 要真实苹果付款

1. Signing & Capabilities 核对 Team（当前沿用 DQK6C4RU3Y）和 Bundle ID；每款 ID 在 manifest.json / products.csv。签名和 Apple 登录能力需匹配实际账号。
2. 在对应 App Store Connect App 创建 Consumable 商品，完整 ID 用 products.csv，不可自行去掉 .v1/.v2/.v3；已有历史商品使用 legacy-products.csv 对照。修改 ID 时需同步游戏源商品表、原生白名单、本地 .storekit 后重构建。
3. 配置线上价格、可销售状态、商品本地化/审核信息，完成付费协议、税务和银行资料；本地 USD 参考价格不是线上自动配置。
4. 切换 Release Scheme（不关联本地 .storekit），完成签名真机或 TestFlight/Sandbox 购买测试，再 Archive/上传。验证苹果付款结果、准确币量、重进余额和重复回调不重复授币。

本方案不需要你自建远程验证服务器，但查询商品和苹果支付仍要联网；是设备本地验证 Apple 签名交易，不是完全离线真实付款。先持久化金币及 transaction ID，再 finish；只恢复未完成消耗型交易，不能无限补领已消费金币。

## 边界

卸载/清存档可能丢账户及金币；不支持云同步、服务器风控或自动退款扣币。WebP 缩小文件，不代表运行内存同比下降。完整数据、实测范围和未验证项见《验证与压缩报告.md》。未经真实沙盒、签名与合规检查，不宣称可以直接上架。
