# Fortune Tides — release gates

This is a browser-playable social casino template, not a submitted or approved native application. Coins are virtual, have no cash value, and cannot be withdrawn. Local rankings contain explicitly labeled example competitors. The shop displays four proposed packs (20,000 / 110,000 / 240,000 / 520,000); the browser build accepts no payments and grants no purchase coins.

## Required before a native release

- Produce and test the actual native package: signing, provisioning, app identifiers, icons, launch screen, orientation, safe areas, accessibility, lifecycle, background audio behavior, offline recovery, device performance, and installation/update migration. A working browser build is not evidence of native readiness.
- Implement the native StoreKit purchase flow and the supporting server verification and entitlement ledger before enabling purchases. Validate product configuration, signed transactions, account association, idempotent coin delivery, pending/canceled purchases, interrupted transactions, refunds and revocations. Restore only supported product entitlements; do not promise restoration of already consumed coin packs. Test in the applicable Apple sandbox and device builds.
- Replace localStorage as the authoritative balance source if transactions or competitive rankings are introduced. This demo uses local, user-editable state and device time; it offers no anti-cheat guarantee, multi-tab synchronization, cross-device recovery, or server identity. Browser storage loss resets progress; unavailable storage falls back to the active session only.
- Review the current Apple submission requirements at submission time: privacy disclosures, actual data collection by all SDKs, privacy manifests and required-reason APIs where applicable, tracking consent where applicable, account/data deletion where applicable, age rating, social casino presentation, consumer disclosures, and regional availability. Document the implemented behavior and obtain any needed specialist review.
- Audit every shipped image, font, sound, trademark, generated-art input, and third-party component. Keep provenance and licenses; confirm distribution and commercial use rights. An asset placeholder or generated asset does not establish rights clearance.
- Validate game math independently for all four modes; verify bet accounting, payout limits, free/bonus event settlement, advertised rules, and actual symbol tables. Keep reproducible statistical results and regression coverage. Do not advertise an RTP or chance of winning without verification.
- Complete real-device QA and language review for English, Simplified Chinese, Traditional Chinese, Japanese, and Korean. Check UI truncation, screen readers, reduced motion, mute behavior, background/resume, repeated reward taps, storage failures, and interrupted spins.
- Prepare truthful store metadata, screenshots, support contact, privacy policy, age rating responses, and review notes that explain virtual currency, lack of cash-out, and actual purchase behavior. Replace example rankings with a clearly specified production service or continue labeling them as examples.

No store review outcome, approval date, revenue, player retention, or regulatory classification is guaranteed by this template. These are engineering release gates, not a claim that any native or legal review has already been completed.
