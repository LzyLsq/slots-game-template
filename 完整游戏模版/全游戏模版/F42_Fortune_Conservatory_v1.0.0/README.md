# F42 · Fortune Conservatory / 金曜财苑

完整的四模式 **虚拟金币 Slots Web 模板**。日光玻璃宫殿、红金与玉绿雕刻柜机、金币财宝装饰；四只非真人招财守护者分别与柜机同图绘制。首次启动默认 **English**，MENU → Language 可切换中文，选择在本机记忆。

## 运行与构建

需要 Node.js 22 或更新版本。运行页面无需安装任何前端依赖。

```sh
npm start
# 默认地址 http://127.0.0.1:6142/
node tools/serve.mjs --port 6143  # 如需另一个端口
npm test
npm run build
```

部署只需 `dist` 中的文件。`dist` 为构建产物，不包含原画、测试与文档。开发服务器仅监听本机，不用于公开生产环境。

## 四种独立规则

| 模式 | 转轴及计奖 | 免费功能 |
| --- | --- | --- |
| Tiger Treasury / 白虎金殿 | 5×3，20条固定线 | 5次免费旋转；连胜逐盘提高下一盘倍率，最高4×，未中重置 |
| Koi Reserve / 锦鲤珠库 | 5×4，1024 Ways | 4次免费旋转；每盘每2颗珍珠增加1×，最高5×，各盘独立 |
| Crane Palace / 仙鹤宝阁 | 4×4，16条双向线 | 4次免费旋转；中间两轴镜像；每线只付左右较高的一次 |
| Treasure Tortoise / 金龟宝藏 | 3×3，8条固定线 | 4次免费旋转；金币留在原格直到本次免费功能结束 |

三颗或更多 LOTUS 触发免费功能，无免费重触发。一局包括其全部免费盘，仅扣除一次下注。下注档位：20 / 50 / 100 / 200 / 500。详情见游戏内 RULES，以及 `src/config.mjs`、`src/math.mjs`。

- 普通奖：`0 < 本局返还 ≤ 下注`；屏幕内金额提示、符号高亮、金币及专属音效。
- BIG WIN：返还大于下注；SUPER WIN：至少10×；MEGA WIN：至少30×，分级舞台、金额递增和金币演出。
- 新手礼遇明确披露：前四个付费结算局若尚未获得10×，第五局独立赠币补足到总10×，单独记账；**不伪造转轴或修改自然 RNG**。
- 数学审计为每模式60,000完整局的固定种子模拟，赠币排除，见 `docs/math-audit.json`。不是认证 RTP，也不是现实收益承诺。

## 完整功能

登录与年龄/虚拟币同意、本机多账户、四模式大厅原位选择并直接进入、柜机滑动切换、下注/手动旋转/最多10局自动旋转、规则与奖励演出、Apple 内购接口（Web 未接原生桥时禁用购买）、每日奖励、四殿收藏进度、示例排行、钱包账本、昵称与四种头像、账户删除、音乐/音效/减弱动态/中英文设置。

每局在动画前以 IndexedDB 原子事务结算，保存待展示结果；刷新后恢复展示，不再次扣注或发币。当前 Web 商店**不付款、不赠送付费商品金币**；仅提供已验证交易的原生桥接接口，尚无真实 StoreKit 实现。排行**不是在线真人排名**，账户只保存在本机。

新红金柜机分别以白虎、锦鲤、仙鹤、金龟雕刻和金锭、铜钱为装饰，完整吉祥物随柜机同图生成，预留固定落脚平台。雕刻金玉图像按钮带按压反馈，PLAY使用独立长比例原画，不压扁短按钮图；大厅与登录使用完整角色图，不再拼接独立手臂；柜机吉祥物使用肩根锁定的局部肢体动作，身体、接触位置与平台保持稳定，减弱动态或 WebGL 不可用时回退到原完整柜机场景。柜机所在房间由四张原画各自向上、向下和右侧扩图；运行时房间与柜机使用同一连续栅格，转轴、标题、角色动画裁片和台面控件共享同一相机变换，没有另一张大厅底图或接缝渐隐。横屏使用完整连续宽景覆盖屏幕，不用大厅图补两侧；仅裁切装饰下底座。横屏模式选择改为两列两行，保留雕刻按钮与金币栏的原画比例。隐藏页面暂停动态与音乐，停止后续自动局；可减弱动态。

柜机台面采用单排 BET / RULES / AUTO / SPIN，BET 打开五档总下注选择，独立命中区不互相覆盖。音效在暂停态预解码，点击只等待对应反馈文件，超过180ms的滞后点击不补播；反馈总线使用柔和动态压缩缓和叠加峰值。这些是运行行为，不代表已完成人工音色/音乐验收。

## 验证与截图

- 66项自动单元测试：规则、免费功能、结算幂等、奖励/账户、英文翻译、单一场景变换、音量淡化、独立反馈解码及角色关节锚定。
- 浏览器完整流程：首次英文、中文选择记忆、四模式、商店/每日/头像、五局礼遇、四级演出及其文字安全边界、资源及音频加载。
- 中断流程：旋转时刷新不重复计币、快速点击不重复结算、快速换模式清理旧场景、账户隔离、减弱动态记忆。
- 角色专项检查：四个完整大厅角色、32个柜机动作阶段、四种静态回退与16次模式切换。
- 36个渲染组合：320×568 / 390×844 / 430×932 / 568×320 / 844×390 / 1280×800，检查文字/符号裁切、控件越界与相互重叠、柜机按钮至少44×44px的实际命中区域及边缘可点，并检查房间与柜机共用同一变换、没有独立底图或渐隐遮罩。
- 上述为 **桌面 Chrome 视口模拟**，不是 iPhone/iPad 真机验证。音频加载/解码已验证；没有把自动测试当成实际人工试听。

本轮固定验收标准见 `docs/design-requirements.md`；它是整改标准，不是全部通过声明。报告在 `docs`，实际渲染截图在 `docs/screenshots`。仅保留主要界面和代表尺寸截图，不保留旧方案与重复输出。

浏览器复测需 Playwright 与浏览器；可安装到本项目，或设置 `PLAYWRIGHT_MODULE` 为其模块入口、`CHROME_EXECUTABLE` 为浏览器路径。先启动服务器，再执行：

```sh
npm run qa:runtime
npm run qa:responsive
npm run qa:workflows
npm run qa:views
npm run qa:guardians
npm run qa:interactions
npm run release:audit
```

可用 `QA_BASE_URL` 更换测试地址。审计对运行源码、实际美术与音频文件的指纹进行匹配，修改源码后必须重跑浏览器 QA。仅本机 `?debug=1` 启用 QA/演出预览；预览不改变余额。普通入口不会绕过登录同意。
