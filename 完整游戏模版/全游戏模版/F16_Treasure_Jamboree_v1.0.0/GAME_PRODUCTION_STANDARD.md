# 完整商业游戏制作与验收规范

整理日期：2026-09-20。来源：用户在 F8–F16 及后续 Treasure Jamboree 制作会话中的明确要求、反馈与否决意见。

本文件用于下一款独立游戏和当前游戏的持续打磨，不是完成声明。历史要求合并为可执行标准；相互冲突时，以用户最近明确指示为准。不得仅因文件存在就宣称“商业级”“最高品质”或“可上架”。

## 1. 交付对象与不可降低的目标

- 交付可运行、完整、可独立打包的游戏，不是设计稿、演示网页、纯图片柜机或只通一个模式的原型。
- 默认四个完整游戏模式；各模式的玩法、规则、转轴结构、主题符号、柜机装饰及反馈必须有合理差异，不能四套外框配相同内容。
- 新产品不能只是换名字、换素材、换颜色。登录、大厅、排行榜、奖励、账户、商店、加载演出和柜机都要形成独立设计。
- 可借鉴既有项目的成熟实现和质量，不选一个旧项目原封不动当底座，不照搬旧 F16 的结构或失败素材。共享可靠基础逻辑不等于复用旧的视觉壳。
- 默认产品可见文案为英语；讨论、制作记录可以中文。不得把中文开发备注漏进英文界面。
- 用户要财富、宝藏、金币、柔和喜庆、轻松欢快、卡通、金光闪闪、华丽但亲切的娱乐体验，不是金融产品、沉重宫殿、网页仪表板或阴森夸张的赌博按钮。
- 不设“最高标准已达”的主观捷径。持续修复发现的问题；遇到签名、账户、授权等外部阻塞时准确说明，不编造验证结果。

## 3. 先确定原创美术体系，再制作资源

- 先列出主题、色彩、光源方向、材质、透视、字体层级、空间结构、动效节奏，比较与参考项目的差异。
- 同一世界的场景、柜机、控制台、按钮、金币、图标和弹窗必须统一。不用随机金边、随意渐变、无意义发光或装饰堆砌掩盖设计不足。
- 财富要有视觉亮点：主题宝物、精致金币浮雕、柜机顶饰、柜台与细节反射；不是把金币撒满屏幕。
- 禁止用旧项目资源冒充新生成资源，禁止只替换少数图后称全新。建立素材来源、生成/加工方式、用途、授权与引用清单。
- 用户曾明确要求本地 CC Switch 生图。涉及生图时先确认可用流程与当前要求；不可静默冒充调用，也不得伪称素材已生成。工具不可用时说明，遵循当轮工具约束。
- 不用 Emoji、系统默认图标或粗制小图标代替正式美术。功能图标要有统一视角、材质和可识别的标志。
- 图片比例保持自然；透明资源真正带干净 alpha，不带矩形底、不夹背景、不漏白边黑边。精灵裁切不得带入邻格符号。
- 图像标题应具有清晰品牌感，可有克制的反光、显现或轻微动态；正文、资产和规则保持高可读性。
- 用户不接受纯色大背景：页面、加载、柜机后方必须有真实场景或有质感的主题表面。提高可读性的局部遮罩不应变成大块空白底或黄底。
- 新资源先做实际比例渲染检查，再批量铺开；不靠越来越多的装饰修补错误方向。

## 4. 场景、柜机与转轴是一套空间系统

- 柜机与背景应自然融为同一场景；外部背景是该场景的延伸，不是另放一张不相关背景、模糊补边、重复拼块或黄色面板。
- “同一图层”的验收含义是同一镜头/坐标/缩放体系和连续光影；技术上可以分层，但不能看到拼接、漂浮、透视冲突、独立缩放或硬接缝。
- 柜机足够大，核心玩法占主要视觉面积；全屏填充但不拉伸，装饰不能挤占按钮与转轴空间。
- 转轴绑定柜机屏幕容器，用相对约束、锚点、统一缩放和裁切适配，不靠一套绝对坐标凑某一台手机。
- 不同设备不得出现轴偏移、半格、异常空隙、符号超框、装饰遮轴、文字覆盖或按钮热区错位。
- 转轴符号统一规格、清晰、适当留白，各模式使用各自完整主题符号；逐个检查 atlas 边缘和缩放。
- 不同柜机的轮廓、顶饰、侧饰、控制台和主题按钮要有区别，但遵守整款游戏统一材质标准。

## 5. 完整页面与大厅体验

- 登录：品牌、动态场景、清晰输入、游客/登录入口、协议、加载、失败与重试。输入失焦不能丢值；密码处理与显示状态正确。
- 大厅：不是几张简单卡片。用完整场景构图或其他原创布局承载四种游戏、资产、充值、奖励、活动、设置和账户，主次清楚。
- 点击方式不统一套模板：每款游戏应根据主题、场景与布局设计有自身特色的交互。直接点击进入、选择预览后进入、滑动浏览等均可采用，不能为了差异化牺牲可理解性，也不能增加无意义的操作。
- 入口外观必须与行为一致：玩家应能判断当前操作是在选择、预览还是进入。选择式入口需要明确的选中反馈和进入位置；直接进入式入口不应误导为需要额外确认。
- 可交互建筑或其他场景对象需要清楚的名称、动作提示或同等明确的视觉线索，不依赖猜测不可见热区。同一游戏的不同入口映射保持一致，不强制所有项目使用常驻名称牌。
- 一次有效操作只触发一次对应动作；按设计区分点击、滑动、拖动与取消，防止手势冲突和误进入。连点和多指不重复跳转；返回大厅后恢复可用状态，不残留 OPENING/ENTERING 等提示。
- 当前 Treasure Jamboree 的独立入口与直接进入方式是该版本的具体方案，不是跨游戏通用要求。用户先前对二次点击的否定针对当时不合适的流程；最新要求是不同游戏的交互各有特色，不一律禁止“选择后进入”。
- 选中、按下、释放、加载、不可用、失败都有明确反馈。不能点了没反应，也不能每点一次黑屏。
- 排行：榜首与列表、自己的位置、时间范围、空态与失败态；不能假榜单冒充在线结果。
- 奖励：可领取条件、已领取/未达成、进度、领取反馈、余额同步与重复领取保护。
- 商店：清晰商品、价格来源、币量、购买状态、失败/取消/处理中、合法恢复机制；没有正式支付配置时不能伪装真实充值。
- 账户：资产/记录、设置、音效音乐、登录退出、支持、隐私、删除账户等入口按实际产品提供。
- 所有页面同等精致，不能大厅华丽、二级页变回粗糙白卡片。

## 6. 按钮、图标与手感

- 圆润、柔和、有光泽和实体厚度，类似克制的果冻弹性，而不是夸张变形、吓人的尖锐边框或粘上去的贴纸。
- 按钮应嵌在自己的控制台环境中，光源、阴影和材质与柜机一致。加减、Spin、Auto、Turbo、返回、充值均要适配主题。
- 按下略下沉，释放自然回弹；不能外框动、图标不动、热区跟着乱跑。
- 当宝物图标、名称和行动提示构成同一个可按压实体时，应有协调的整体反馈，避免割裂感；若承担不同操作则明确区分。热区稳定，视觉动画不引起误触，不为播放回弹强制增加明显等待。
- 不同按钮按职责设计，不是全套复制同一个底片；功能意义保持一致，不以新奇牺牲辨识度。
- 每个按钮真实可用，具备默认/按下/选中/禁用/加载/成功/失败中的适用状态。
- 投注上下限、余额不足、旋转锁定、连点、多指、取消、拖出后松手均有保护。禁用操作不播放成功音效或误报成功。
- 安全区内单手可达；触控区域至少以 44pt 为设计目标，视觉尺寸和实际热区分别验证。

## 7. 动效、加载与中奖演出

- 自然、连续、欢快、灵动，不要死气沉沉，也不要所有元素同时摇晃、闪烁或呼吸。
- 背景柔光流动、局部金币反光、柜机材质反射、标题微动、页面/弹窗过渡组成有层次的节奏。
- 柜台周围也要有适合主题的动态细节：沿金属边缘缓慢移动的反光、宝物局部闪点、少量轻轻上浮的金色微粒。效果贴合柜台材质与光源，不是另贴一层无关装饰。
- 柜台特效错峰出现、柔和亮起淡出，避免整圈同步闪烁、高频闪光或满屏撒币。实际运行时应能感受到灵动，但文字、余额、游戏符号和操作反馈始终优先。
- 特效绑定柜台容器，随柜台统一缩放与定位；避开文字和主要点击区域，装饰节点不拦截输入。小屏、长屏均检查边缘裁切与遮挡。
- 常驻特效使用有上限的预建节点或对象池，不每帧创建对象；离页清理事件与动画，后台暂停，恢复不集中补播。减少动态效果模式关闭或显著简化这类环境动效。
- 旋转有启动预备、加速、匀速、减速、逐轴停止、轻回弹和精准归位。普通/快速/自动模式逻辑一致但时长适配。
- 比较 S05 的真实运行手感，不能只在代码中写 easing 就认为丝滑。
- 加载演出使用目标游戏的主题宝物和图像标题，有聚焦、清晰阶段、完成收尾与连续揭幕。真实进度不倒退、不靠假百分比等待，不先显示 Ready 再加载资源。
- 不为了完整播放动画强迫玩家等长演出；缓存路径更快，加载失败可恢复并重试，不锁死输入。
- 中奖必须看得懂：标出获奖符号、中奖线/区域、组合、倍率与金额，规则写清楚。不能只有撒币而看不出哪里中。
- 中奖顺序：符号/线提示 → 奖励重点演出 → 数字递增/金币入账反馈 → 精确最终金额。小奖与大奖分级，有节奏，不能遮住关键资产。
- 允许跳过长演出时直接显示最终结果，不截断结算。不重复扣款、不重复派奖。
- 音乐、按钮、启转、停轴、中奖声与动作同步；开关可用并持久化。后台暂停不必要动画和音效，恢复不重复播放或自动下注。
- 尊重 reduced motion；减少粒子、平移/闪动，保留清楚的状态反馈。

## 8. 账户、资金与服务边界

- 登录、大厅、游戏、奖励、商店和账户共享真实状态，不只是改几个 Label。
- 投注扣款、结果生成/确认、派奖采用明确状态机和幂等交易标识；重复请求、重试和网络恢复不会重复交易。
- 金额用一致的整数单位或明确精度，显示、规则、投注和账本一致，禁止浮点误差累计。
- 余额不足提示明确，旋转过程中不可改变已提交投注；快速/自动不会绕过校验。
- 切页、重进、刷新、前后台、断网恢复后校验资产；本地缓存不是正式服务端权威账本。
- 正式产品需要鉴权、生产持久化、请求校验、可靠结算与监控。测试币、模拟服务、debug 强制结果必须与发布环境隔离。
- 非法输入、服务超时、失败重试、处理中与重复点击必须用真实异常路径验证。

## 9. 独立 App Store 发布门槛

这是提交前检查表，不承诺审核通过。每款游戏必须重新查 Apple 当期要求、目标地区要求，并区分虚拟币娱乐与真实货币赌博。

- 默认范围是不可提现、不兑换现金或现实奖品的虚拟币娱乐游戏。历史“赌博氛围”的说法不是新增现金下注/提现业务的授权。
- 若改为真实货币赌博，必须单独确认法律、牌照、地域限制与 Apple 分类要求；不能沿用虚拟币 IAP 方案。
- 独立 bundle ID、应用名、图标、启动资源、签名、版本号和正式构建；不能把本地网页能跑等同于原生已通过验证。
- 正式数字商品购买采用适用的 StoreKit 流程；交易验证、唯一 transaction ID、重复回调、未完成交易、取消、待批准、失败、退款/撤销处理有证据。
- 恢复购买按商品类型实现，不能声称消耗型金币可由一个 Restore 按钮无限补领；以权威账本和适用平台机制核对。
- 没有真实产品 ID、App Store Connect 配置、证书、服务端凭据或 Sandbox 测试结果时，列为发布阻塞，不伪造“已充值成功”。
- 隐私政策、条款、支持联系方式、数据收集披露、权限目的、适用的隐私清单/SDK 声明、登录方案和应用内账户删除逐项核验。
- 年龄分级、模拟赌博/购买随机物品等问卷如实填写；适用时披露随机购买概率。不得默认用卡通就能面向儿童。
- 字体、图片、音效、音乐、代码及生成素材的商业授权与来源留档，不假定“生成的就没有版权风险”。
- 真实设备、安全区、性能、内存、崩溃日志、生产网络、冷启动、断网、长期运行、购买恢复均有验收记录。
- App Store 截图对应真实当前版本；元数据、测试账号/审核说明真实完整。用户要求 Git 上传时，代码和对应名称截图一起提交，核实截图确实被跟踪上传。
- 技术模板可就绪、原生集成可就绪、提交包可就绪、审核通过是四种不同状态，交付时分开报告。

## 12. 本会话必须避免的失败模式

1. 只换皮并称全新；四个模式一样；按钮和装饰机械复制。
2. 大厅仅几张简单卡片、交互机械照搬、选中不明显、反馈太少、入口行为与外观不一致或存在无意义的额外步骤。
3. 柜机太小、背景不延伸、有纯黄底、硬拼接、漂浮、像插图贴上去。
4. 按钮锋利吓人、粗糙无光泽、加减不适配、金币没有精致标志。
5. 静态、僵硬、重复循环、切页黑屏；只看截图，不参考 S05 实际动态。
6. 未加载图片、透明失败、图标边缘夹入其他符号、资源重复与旧素材冒充原创。
7. 不显示资产、不说明哪里中奖、规则含糊、数字与实际结算不一致。
8. 输入字体小、失焦内容消失、文字重叠、按钮被安全区挡住。
9. 本地演示当正式购买、未测试就称可上架、只交效果图不交完整游戏。
10. 未完成便泛泛总结，或以“最高水平”口号替代修复和实际证据。
